# 프로덕션 출시 전 체크리스트

> 목적: 클로즈드 테스트 **14일 게이트 통과 후**, 공개 프로덕션 출시 전에 확인한다. 기준일: **2026-10-02 (KST)**

## 1. Play 출시 게이트

- [ ] 옵트인한 클로즈드 테스터 **12명 이상**을 **14일 이상** 유지했는지 확인한다.
- [ ] 14일 게이트를 통과한 뒤 Play Console에서 **프로덕션 액세스 신청**을 한다.
- [ ] 액세스 승인 후 릴리스를 **프로덕션 트랙으로 승격·출시**한다.

## 2. 프로덕션 전 UI polish

- [ ] 주요 화면의 레이아웃, 로딩·빈 상태·오류 상태, 문구, CTA를 실기기에서 최종 점검한다.
- [ ] 잘림·겹침·느린 지역 전환·잘못된 지역 콘텐츠가 없고, 공개 빌드에서 테스트 문구가 남지 않았는지 확인한다.

## 3. 실제 광고 연동

- [ ] placeholder/테스트 광고가 아닌 **실제 AdMob 앱·광고 단위 ID**를 운영 빌드에 연동한다.
- [ ] ATT/AD_ID 고지와 광고 표시를 실제 기기에서 확인한다. (구현계획서 §11의 R18)

## 4. 남은 도시·지역 범위

- [ ] 남은 광역시·대도시의 **APPLY 게시판**을 적용한다(서울·대구·인천·대전·울산·광주 등 Phase 1 대상).
- [ ] APPLY 수집·검수·daily 반영 등 **지역별 잔여 레지스터 작업**을 마치거나, 미제공 상태를 정직하게 표시한다.
- [ ] 데이터가 얇은 관광도시는 문화포털 등으로 **ENJOY 보강**하고, 계속 얇은 도시는 모니터링한다.
- [ ] [구현계획서 §11 잔여·이월 레지스터](../구현계획서.md#11-잔여이월-레지스터)의 **R25–R32**를 재확인하고 각 상태(Open/Partial/Deferred/Done)와 다음 조치를 문서와 일치시킨다. 새 잔여 ID는 임의로 만들지 않는다.

## 5. 스토어·정책 최종 확인

- [ ] 스토어 등록정보, **비정부 서비스 면책 문구**, 원문·출처 URL이 현재 동작과 일치한다.
- [ ] Play 정책·콘텐츠 설문/질문지가 최신 상태이고, 광고·데이터 수집 고지가 실제 빌드와 일치한다.

## 6. 최종 도그푸딩·증거

- [ ] **R20 휴대폰 도그푸딩**이 아직 열려 있으면 출시 전에 수행하고, 결과를 구현계획서 §11에 반영한다.
- [ ] 공개할 릴리스 후보에서 핵심 도시 전환, APPLY/ENJOY/DISCOVER, 원문 CTA를 최종 확인하고 출시 기록을 남긴다.
