## 1. 짧은 설명 (기본 등록정보 교체 초안)

Play 짧은 설명 한도 80자. 아래 AFTER는 **47자**(공백·쉼표·마침표 포함).

검색 결과처럼 상세 페이지 밖에도 나올 수 있어, 첫 구절은 비제휴다. 이모지, 「다운로드」「설치」, 순위·가격 문구는 없다.

### BEFORE (현재 게시·`listing-ko.md` 그대로)

```
민간 비제휴 안내 앱입니다. 공개 공고를 모아 「공식 원문 보기」로만 안내합니다.
```

45자. 비제휴와 원문 안내는 있으나, 축제·행사·체험이 없다.

### AFTER (제안 · 콘솔에 아직 붙이지 않음)

```
민간 비제휴 안내. 고른 지역의 축제, 행사, 체험을 모으고 공식 원문만 안내합니다.
```

`play-free-growth-draft-2026-10-26.md` §1.5와 같은 문장이다. 기본 등록정보용 초안과 맞춤 등록정보 초안이 서로 다른 약속을 하지 않게 맞춘 것이다. 맞춤 등록정보를 만들라는 뜻이 아니다.

### 이 문장이 지키는 것

- **비제휴를 앞에 둔다.** 「민간 비제휴 안내」로 시작한다. 정부·지자체·한국관광공사 공식 앱, 제휴, 위탁을 말하지 않는다.
- **축제 / 행사 / 체험**을 한 줄에 넣는다. 맞춤 등록정보 테마(고른 지역의 축제·행사·체험, 참가는 공식 원문)와 같다.
- **VisitKorea만 출처로 두는 자세를 유지한다.** 이 짧은 설명은 새 호스트를 적지 않는다. 긴 설명은 이 초안에서 바꾸지 않으며, 지금 긴 설명에 있는 출처 URL은 VisitKorea 영문과 TourAPI뿐이다. 「공식 원문만」은 그 원문 확인 자세이고, 복지로·보조금24·`.go.kr`을 짧은 설명에 넣지 않는다.
- 지원금, 보조금, 고시공고, 시청 앱, 1위, 인기처럼 오인되거나 메타데이터 정책에 걸리는 단어는 넣지 않는다.

### 콘솔에서 하지 말 것

- 이 AFTER를 기본 등록정보 짧은 설명에 붙여 저장하지 않는다.
- 긴 설명을 이 파일 때문에 갈아끼우지 않는다. Gemini 제안문도 쓰지 않는다.
- 맞춤 등록정보 `한국-검색-지역축제체험`를 이 초안과 함께 게시하지 않는다.
- 대한민국을 국가 타겟 맞춤 등록정보에 넣지 않는다.

## 2. 첫 휴대폰 스크린샷 브리프

이미지 파일은 만들지 않았다. 구도와 촬영 순서만 적는다. 근거는 `docs/store/play-free-growth-draft-2026-10-26.md` §2.5다. §2 실험은 시작하지 않는다. 이 절은 나중에 기본 등록정보의 **첫 장**을 바꿀 때의 촬영 지시이고, 지금 콘솔에 올리는 절차가 아니다.

화면은 합성 UI가 아니다. 기기에 설치된 앱이 서버·캐시 피드로 그린 「곧 열리는 행사」목록의 캡처만 쓴다. 카드 제목과 날짜를 새로 짓지 않는다.

### 2.1 저장소에 있는 파일 — 이 구도와 맞지 않음

아래는 첫 장 교체본이 아니다. 실사 「곧 열리는 행사」목록이 없다.

| 경로 | 왜 쓰지 않는지 |
|------|----------------|
| `docs/store/screenshots/play/01-home.png` | 홈. 수원 히어로, 「지금 신청할 수 있어요」, 주민자치 수강. 상단에 `suwon.go.kr`이 들어간 면책 예시가 있다. 현재 프로덕션 첫 장 참고본으로만 둔다. 덮어쓰지 않는다 |
| `docs/store/screenshots/phone/01-home.png` | 같은 홈. 하단에 테스트 광고가 있다 |
| `docs/store/screenshots/play/05-apply-list.png` | 제목이 신청 목록 쪽이고 카드가 강좌·모집 공고다. 행사 목록이 아니다 |
| `docs/store/screenshots/phone/06-apply-list.png` | 신청 목록 원본 |
| `docs/store/screenshots/03-enjoy-section.webp` | 웹 프리뷰·자리표시. 폰의 「곧 열리는 행사」전체 목록이 아니다 |

### 2.2 열 화면

코드 기준 경로다.

1. 앱을 연다. 지역이 없으면 지역 선택 후, 첫 실행이면 사는 곳 / 여행·체류를 고르고 홈으로 온다. 이미 지역이 있으면 홈이다.
2. 홈 퀵 카테고리에서 **「곧 열리는 행사」**를 누른다. 아이콘 줄의 두 번째, 라벨은 `곧 열리는` / `행사` (`HomeTab` → `MainShell._onQuickCategory` case 1).
3. 푸시된 화면의 AppBar 제목이 **`곧 열리는 행사`**인지 확인한다. 위젯은 `OpportunityListScreen`이고, 목록 본문은 `OpportunityTab`이다. 홈의 「곧 열려요」섹션을 홈에 그대로 찍지 않는다. 발견 탭도 아니다.
4. 행사가 여러 장 보이는 지역을 고른다. 목록이 0건이거나 1건이면 그 도시로 찍지 않고 다른 지역으로 바꾼다. 도시 이름은 이 문서에 단정하지 않는다. 찍는 날의 피드에 카드가 여러 장 있는 지역만 쓴다.

### 2.3 프레임

- 세로. 지금 Play 휴대폰 스크린샷과 같은 비율.
- 행사 카드 **2–3장**이 보이게 한다. 각 카드에는 피드에 있는 제목, 그리고 날짜 또는 D-day가 있다 (`OpportunityCard`). 글자를 다시 쓰지 않는다.
- 목록 광고는 첫·둘째 카드 뒤에 들어오지 않고, 셋째 카드 다음에 네이티브 칸이 붙을 수 있다 (`AdConfig.shouldInsertFeedAdAfterCardIndex`). 위쪽 행사 카드만 프레임에 두고, 「광고」칸은 프레임 밖에 둔다. 광고를 지우는 합성은 하지 않는다. 테스트 광고 띠가 보이면 그 캡처는 쓰지 않는다.
- 이 목록은 하단 탭 바 없는 푸시 화면이다. 홈 하단 배너는 0.1.12에서 셸에서 뺐다. 하단에 광고 자리를 다시 붙여 찍지 않는다.
- **면책 띠가 화면에 있으면 남긴다.** 반을 덮으면, 띠가 한 줄만 남도록 스크롤한다. 띠를 지운 합성은 하지 않는다. 2026-10-27 코드의 `OpportunityListScreen`에는 상단 면책 띠가 없다. 없는데 예전의 `suwon.go.kr` 문장을 덧대어 넣지 않는다.
- 글자를 덧씌운다면 한 줄만. `고른 지역의 이번 행사·체험`. 둘째 줄이 필요하면 `민간 앱 · 공공기관을 대표하지 않음`. 덧씌운 글자가 카드를 가리면 덧씌우지 않고 목록만 쓴다. 리본, 배지, 형광 스티커, 별점, 「1위」, 「공식」, 「지원금」, 가격, 설치 유도는 넣지 않는다.

### 2.4 넣지 말 것

- `.go.kr` 주소 오버레이. `01-home.png`의 `https://www.suwon.go.kr` 예시를 이 장에 다시 넣지 않는다.
- 복지로, 보조금24, 정부24.
- 태극·정부·지자체 휘장, 가짜 배지, 「공식 앱」.
- 행사 이름을 지어 그린 가짜 화면, 목업, 빈 카드에 글자만 올린 이미지.
- 아이콘 파일. 2장째 이후 스크린샷 교체. 이 브리프는 첫 장만 다룬다.

### 2.5 파일 경로

새 PNG가 생기면 여기에만 둔다.

`docs/store/screenshots/play/01-upcoming-events.png`

- `01-home.png`를 이 파일로 갈아끼우지 않는다. `01-home.png`는 지금 프로덕션 첫 장과 §2 실험의 대조군 참고다.
- 콘솔의 휴대폰 스크린샷 **첫 슬롯**에 올릴 후보는 `01-upcoming-events.png`다. 파일명 앞의 `01-`는 그 슬롯을 가리킨다.
- 실기기 원본을 따로 남기면 `docs/store/screenshots/phone/01-upcoming-events.png`. Play용은 테스트 광고가 프레임에 없는 장이다.

### 2.6 콘솔

**Play Console 업로드는 동수님 OK가 나기 전에는 하지 않는다.**

OK 이후에도 이 문서가 실험 시작을 허락하지 않는다. `play-free-growth-draft-2026-10-26.md` §2.6의 보관 조건(방문·예상 기간)을 충족하기 전에는 그래픽 실험을 열지 않는다. 실험을 열 때도 아이콘은 그대로 두고, 첫 장만 B로 둔다.
